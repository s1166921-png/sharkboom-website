# SharkBoom 审核、报价与支付订单系统

**Goal:** 落实用户已确认的六步流程，提供管理员登录、真实交易核验与出单跟进。

**Architecture:** 保留静态 3D 官网，独立 Node.js 24 服务通过同域 /api、/admin、/orders 提供订单功能。SQLite 持久化，客户资料与订单内容加密存储，客户私密链接与管理员会话隔离。支付仅使用官方渠道，未配置商户参数时关闭收款。

**Tech Stack:** Node HTTP、node:sqlite、scrypt、AES-256-GCM、官方支付宝 SDK、微信支付 API v3、现有 React 首页。

**Spec:** 用户本轮明确要求的资料 → 人审报价 → 确认明细 → 官方收银台 → 后台核验 → 出单。

## Constraints

- 不修改 3D 场景；保留 Excel 导出与既有产品顺序、联系资料。
- 保费/服务费分项、每项指定已配置收款主体，人民币按分记账，不将展示起价当作最终报价。
- 支付成功仅来自签名验证的回调或查询；客户、管理员均不能手动标记支付成功。
- 保费支付不等于保险生效；人工出单记录独立。
- 商户密钥、账号密码、数据库、客户链接不入仓库；后台禁止缓存和搜索收录。

## Review focus

- 客户越权访问其他订单、跨站操作、无会话后台访问：HTTP 集成测试应拒绝。
- 客户确认后改价、未确认付款、重复支付请求：版本与状态机测试应拒绝。
- 伪造回调、金额/商户不符、重复流水：真实 RSA/AES 测试与幂等交易测试。
- 服务重启/并发回调：SQLite 事务与持久化测试。
- 支付参数缺失：无假支付入口，仍可提交审核、报价与跟进。

- 管理员用户名问题未获回复，采用 `sharkboom` 和独立随机初始密码，桌面私有文件交付，首次登录必须改密。
- 按执行技能进行只读独立审查；修复支付宝时间格式、标准查询字段、未建单恢复、微信查询订单绑定及公平查款，新增回归测试。补充未收款订单的显式撤回与重新确认流程，保留原报价和确认记录。目前 14 个订单/支付测试通过。
- 浏览器以临时内存数据库验证提交、后台可见、发布报价、客户确认、报价锁定、未配置支付时无收款入口；手机 390px 客户页无横向溢出。
- Ruling: 商户参数未提供时，只开通资料/审核/报价/确认/跟进页面，生产收款关闭。直接商户的微信 Native 与支付宝网站适配已编写，但尚未做真实交易验证；服务商模式不作假设。
- 正式部署已验证 HTTPS、私有页面 no-store/CSP/noindex、初始登录强制改密、后台未授权拒绝、退出会话失效、秘密路径拒绝与空生产库。服务非 root 运行，每日备份已实际执行；原始 3D、弹窗与二维码公网检查通过。
- 部署排障：首次新建代码父目录受 umask 077 影响，服务账户无法遍历；验证 CHDIR 日志后将无秘密的代码目录改为 0755、文件 0644，保持数据与密钥私有权限。Nginx reload 采用等待及有限重试后健康检查，避免旧 worker 切换窗口造成误判。
